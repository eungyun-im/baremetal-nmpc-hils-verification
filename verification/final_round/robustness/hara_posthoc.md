# 사후 위험 분석 초안 (2026-11-12)

**성격:** 요구사항(SR-01~07)을 정한 **뒤에** 거꾸로 만든 위험 분석이다. ISO 26262 의 HARA(아이템 정의, S·E·C 평가, ASIL 결정, 평가자 검토)를 한 것이 아니며, 그 준수를 주장하지 않는다. 목적은 "어떤 위험을 어떤 요구사항이 막는지"와 "막지 않는 위험이 무엇인지"를 보이는 것이다. S·E·C 는 평가하지 않았다(미평가).

범위: MCU 제어기(MPC + 안전 제어기)와 PC↔MCU CAN 링크. 인지·위치 추정·경로 계획(PC)은 범위 밖.

안전 목표(명세): **SG-01 의도하지 않은 급조향으로 차로를 이탈하지 않는다.**

| # | 위험 상황 (오동작 → 차량 영향) | 막는 요구사항 | 관측 근거 (공식 + 보충) | 빈틈 |
|---|---|---|---|---|
| H1 | MPC 가 그럴듯하지 않은 조향을 냄 → 급조향, 차로 이탈 | SR-05 조향 타당성 검사 | 10° 스텝 검출, 10 s 오차 ≤ 0.8 m (직선에 가까운 두 곳, 공식 2 + 보충 4랩). 4~10° 결함의 1.7 → 0.2~0.6 m 는 이전 펌웨어 자료 | **미해결 DEF-4: 곡선에서 검사가 약 0.5 s 에 풀리고 복귀 때 −19° 를 잘못 붙잡음. 최종 펌웨어로 곡선 시험 안 함.** 4° 미만의 느린 오차는 검출 대상이 아님 |
| H2 | 제어 명령이 끊김 → 마지막 명령 유지로 곡선에서 이탈 | SR-01 두절 → 안전 정지 | 185~186 ms (기준 지점이 아닌 두 곳) | 기준 290 ms 는 가정 차로 폭 기준. 실측 폭이면 약 250~270 ms(`README.md` 1절). 안전 정지는 조향을 마지막 값으로 유지하므로 정지 뒤 차로 유지는 판정하지 않음 |
| H3 | CAN 버스오프 → 명령·응답 모두 끊김 | SR-03 버스오프 → 안전 정지 | 안전 정지 상태는 확인. **MCU 가 들어간 시각은 미측정**(PC 는 버스 복귀 뒤 약 830 ms 에 처음 관측) | **시간 기준이 명세에 없고, 시험 방법으로도 시간을 잴 수 없었다** |
| H4 | 손상된 프레임을 그대로 씀 → 엉뚱한 명령 | SR-07 CRC 오류 폐기 | 요청·차량 CRC 손상에서 정지 없이 주행 유지 | 연속 손상이 길어질 때의 동작은 SR-01 에 맡김 |
| H5 | 차속 신호 상실 → 모델이 틀린 속도로 계산 | SR-02 → 성능 저하 모드 | 173~181 ms | 성능 저하 모드에서의 추종 성능은 따로 판정하지 않음 |

| H7 | MCU 멈춤 → 명령 없음 | SR-06 워치독 리셋 | 198 ms, 정상 복귀 | 미해결 DEF-32: 리셋 뒤 정상 복귀까지 약 2.5 s. 복귀 시간 기준이 없다 |
| H8 | **계산이 늦어 주기를 넘김** → 늦은 명령 | 안전 요구사항 없음 (NFR-01·02 는 성능 요구). 미해결 DEF-31: 펌웨어에 풀이 마감·예산 처리가 없다 | 장시간 시험에서 풀이 30.7 ms 1회, 제어 한 주기 50 ms 초과 2랩. 응답 시간 초과(45 ms)는 링크 실패로 처리 | 늦은 명령이 차량에 주는 영향은 분석하지 않음 |

## 정리
- SR-01~07 은 H1~H7 을 막는다. 공식 판정에서 모두 충족이다.
- **명세가 막지 않는 위험:** H3 의 시간(버스오프, 기준도 측정도 없음), H8 주기 초과(DEF-31), H9 출발 전 입력(DEF-38), H10 가속. H1 은 곡선에서의 미해결 결함(DEF-4)이 남아 있다. 다음 판의 명세에서 요구사항으로 다뤄야 한다.
- 기준 290 ms 자체도 가정값에 기대고 있어, 실측 차로 폭으로는 더 짧다.
